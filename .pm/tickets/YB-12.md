# Description


[Claude Sonnet 4.6]

## Problem Statement
The Thai (Kedmanee) layout is the primary use-case driver. All map data and keyboard grid rows must be seeded as a `LanguageModule` value as specified in SPEC §6.

## Solution Approach
Create `modules/thai.go` containing the `ThaiModule` variable populated verbatim from the spec. No logic — pure data.

## Data (from SPEC §6 — reproduce exactly)
- `ID`: `"thai"`, `Name`: `"Thai (Kedmanee)"`, `Enabled`: `true`
- `DirectMap`: 27 entries (`a`-`z` minus some, see spec)
- `ShiftDirectMap`: 27 entries (uppercase letters as keys)
- `PhoneticMap`: 7 entries with multiple candidates each
- `KeyboardRows`: 4 rows, **must match `StandardRowLengths = [13, 13, 11, 10]`** exactly — each entry must include `Key` (the physical English key label). The spec shows 12 keys in row 0; confirm whether `=` (maps to ว/ซ in Kedmanee) is missing and add it or `EmptyKey("=")` as needed to reach 13.

## Implementation Steps
- [ ] Create `modules/thai.go`
- [ ] Declare `var ThaiModule = LanguageModule{...}` matching SPEC §6.1 exactly
- [ ] Populate `DirectMap` (27 key mappings)
- [ ] Populate `ShiftDirectMap` (27 shifted key mappings)
- [ ] Populate `PhoneticMap` (7 phonetic groups: s, t, k, p, a, i, u)
- [ ] Populate `KeyboardRows` (4 rows, totals must be [13, 13, 11, 10])
- [ ] Confirm whether `=` key belongs in row 0 (standard Kedmanee: ว/ซ) and add it; if genuinely unused add `EmptyKey("=")`
- [ ] Call `ValidateModule(ThaiModule)` in a test or init — must return `nil`
- [ ] Register `ThaiModule` in the model's `languages` slice in `main.go`
- [ ] Confirm `go vet ./...` passes

## Acceptance Criteria
- [ ] `ThaiModule` compiles with correct types
- [ ] Pressing `d` in DirectMode produces `ก`
- [ ] Pressing `Shift+D` produces `ฏ`
- [ ] In SearchMode, query `"s"` yields candidates `ส ษ ศ ซ`
- [ ] Keyboard grid row 0 starts with `VisualKey{Key: "`", Normal: "ๅ", Shift: "+"}`
- [ ] Module is enabled by default (`Enabled: true`)

## Edge Cases
- Some DirectMap keys map to combining Thai vowel/tone marks (e.g. `"h": "้"`); these are single Unicode code points and must be preserved as-is
- Thai characters are multi-byte in UTF-8; ensure source file is saved as UTF-8
