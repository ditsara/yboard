# Description


[Claude Sonnet 4.6]

## Problem Statement
The primary purpose of the app is to pipe composed text to the system clipboard. This must work across WSL (clip.exe), Wayland (wl-copy), and X11 (xclip) without any configuration from the user.

## Solution Approach
Implement `executeClipboardCopy(buffer string) string` exactly as specified in SPEC §5. Probe available tools in priority order: `clip.exe` → `wl-copy` → `xclip`. Pipe buffer via stdin.

## Implementation (from SPEC)
```go
func executeClipboardCopy(buffer string) string {
    if len(buffer) == 0 { return "Buffer empty" }

    var cmd *exec.Cmd
    if _, err := exec.LookPath("clip.exe"); err == nil {
        cmd = exec.Command("clip.exe")
    } else if _, err := exec.LookPath("wl-copy"); err == nil {
        cmd = exec.Command("wl-copy")
    } else {
        cmd = exec.Command("xclip", "-selection", "clipboard")
    }

    cmd.Stdin = strings.NewReader(buffer)
    if err := cmd.Run(); err == nil {
        return "📋 Copied text block to clipboard!"
    }
    return "❌ Clipboard process pipeline error"
}
```

## Trigger Points
| Trigger | Behaviour |
|---------|-----------|
| **F9** | Copy buffer to clipboard; do NOT clear buffer |
| **Enter** | Copy buffer to clipboard AND clear buffer (`wordBuffer = nil`) |

## Implementation Steps
- [ ] Create `clipboard.go` with `executeClipboardCopy(buffer string) string`
- [ ] Implement tool detection in priority order: `clip.exe` → `wl-copy` → `xclip`
- [ ] Pipe buffer string via `cmd.Stdin`
- [ ] Return appropriate status strings on success/failure/empty
- [ ] Handle F9 in `updateTyping`: call copy, set `statusMessage`, keep buffer
- [ ] Handle Enter in `updateTyping`: call copy, set `statusMessage`, clear `wordBuffer`

## Acceptance Criteria
- [ ] F9 copies current buffer to clipboard and shows `"📋 Copied text block to clipboard!"`
- [ ] Enter copies and clears buffer, shows copy confirmation
- [ ] Empty buffer returns `"Buffer empty"` status (no clipboard call attempted)
- [ ] Clipboard error returns `"❌ Clipboard process pipeline error"`
- [ ] Works on WSL (clip.exe preferred), Wayland (wl-copy), and X11 (xclip)

## Edge Cases
- If none of the three tools are available, `xclip` will be attempted and fail → error message shown (acceptable behaviour; no silent failure)
- Multi-line buffers (with spaces) must be passed as-is — no encoding transformation
